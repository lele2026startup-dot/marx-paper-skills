# 马理论期刊稿排版

先读同一 skills 根目录的 `marx-paper/references/workflow-contract.md` 和论文目录任务要求.md。保留用户确认的真尾注、内置双栏默认及模板优先规则；每处引用保留，文献条目按来源去重。

## 输入与模板

沿用已有模板与元信息；只问缺失项。没有指定模板时采用内置三节结构：单栏题目区→双栏正文及参考文献→可选英文部分与作者简介。用户指定单栏或其他结构时按模板调整任务副本的参数，不擅自改公共 skill 的默认模板。

MD 推荐格式：`# 标题`、`**摘要：**`、`**关键词：**`、`## 一、标题`、正文 `[N]`、`## 参考文献` 下 `[N] 完整条目`。也接受简单 YAML title 和 Pandoc `[^id]` 加完整定义；脚本自动转换，不要求用户手工重新录入。组合引用 `[1,2]`/`[1-3]` 暂不支持，先展开成 `[1][2]`，脚本遇到时会拒绝。

meta.json：author、affiliation、author_bio 必填；contact、fund、received、clc、doc_code 可选，english 可选对象含 title/author/affiliation/abstract/keywords。个人信息只存当次论文目录，不进 skill 仓库。中图分类号由选题与模板决定，未提供时不自动猜填。

## 工作流程

1. 读草稿、任务要求、素材核验状态；核对各引用号和实际来源。未核实信息在工作稿和报告里标清。
2. 准备正文与 meta.json，保存到论文目录；不要改掉每处引用，也不要把未读原件的页码改成已核。
3. 运行 `python scripts/build_journal_docx.py --md 正文.md --meta meta.json --out 投稿版.docx`。脚本路径解析为绝对路径。可选 --no-english；已有输出默认拒绝，已获覆盖授权时加 --overwrite，并保留脚本生成的旧文件备份。
4. 首次出现建一个真尾注；重复来源位置建链接该尾注的 Word NOTEREF 域，保留上标方括号。每条来源的文献内容仅一条，不生成隐藏重复条目。
5. 脚本在发布前验证临时文件：引用位置总数、尾注目标、交叉引用书签和编号、无残留标注、作者简介与参考文献标题。失败不发布文件，不覆盖原成果。
6. 用可用 documents/pdf 工具或目标 Word/WPS 渲染检查栏数、分页、上标、尾注位置和点击跳转。有 NOTEREF 时在目标程序更新域并复核；未做视觉/程序兼容性检查须说明，不能把XML通过当成排版验收。

## 引用规则

按首次出现顺序编号；相同编号可在多处引用。完全相同著录条目可合并；不同版本或不同定位信息不作猜测合并。未引用条目会报告并从引文表排除；需要另附阅读书目时单列。

引文具体定位和文章出版起止页码不同：正文或附注中保留需要的具体定位，文献条目按目标模板保留出版范围。顺序编码不能作为删除页码证据的理由。

## 依赖与技术细节

python-docx、lxml；交付前需可用的目标文字处理器或渲染能力。见 `references/journal-endnotes.md` 的 XML、域和版式说明。WPS 重新保存可能改变尾注位置，复核正文后、英文前的列表位置；发生问题从源稿重建并保留全部引注。
