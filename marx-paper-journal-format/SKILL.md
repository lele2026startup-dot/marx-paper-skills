# 马理论科期刊投稿式排版（顺序编码真尾注）

## 这个 skill 做什么

把马理论科的**期刊投稿/征文投稿**论文草稿加工成可直接投稿的 Word 文档。核心特征：

- **顺序编码制真尾注**：文中上标 `[N]`（Word 真尾注，可点击跳转、自动编号），文末参考文献随尾注渲染，`[N]` + GB/T 7714 条目
- **一文一引**：每篇文献只在文中引用一次，从根上避免重复引用的复杂处理
- **内置双栏期刊模板**：题目/作者/单位/摘要/关键词/中图分类号 → 双栏正文 → 参考文献 → 英文部分 → 文末作者简介，全套版式开箱即用
- **作者简介双处**：第一页页下脚注（模板要求）+ 文末完整段含联系方式（征文通知常见要求）

**与 marx-paper-thesis-format 的分工**（二者并列二选一，按场景路由）：

| | marx-paper-thesis-format | 本 skill（marx-paper-journal-format） |
|---|---|---|
| 场景 | 课程论文、期末论文、学位论文 | 期刊投稿、研讨会征文、学报投稿 |
| 引注 | 页下注圈码 ①②③，每页重编号，标具体页码 | 顺序编码真尾注，文中上标 [N]，不带页码 |
| 版式 | 单栏、小四、1.5 倍行距 | 双栏、五号正文、单倍行距、带英文部分 |

## 三条铁律

1. **真尾注，不做假尾注**：文中 `[N]` 必须是 Word 尾注字段，不能用纯文本假上标。用户对这一点有明确要求，纯文本方案会被退回。技术实现见 `references/journal-endnotes.md`。
2. **一文一引**：每篇文献只引用一次。写作阶段就要有意识遵守；格式化阶段脚本会检测重复标注（保留首次、删掉后面的、在报告里列出）。同一文献确实要多次引用且期刊要求独立编号时，才启用备用的"合并编号+隐藏条目"方案（见 references 第 3 节）。
3. **文献信息绝不编造**：参考文献条目（作者、题名、刊名、年、期、起止页码）必须来自用户的真实文献（参考论文文件夹、知网检索结果）。顺序编码制虽不要求标注引文的具体页码，但条目本身的信息必须真实。查不到就标注"[待核实]"并在对话里列出来请用户补，严禁编一个"看起来合理"的条目。

## 工作流

### 第〇步：确认模板 + 收集元信息（开头先问）

**先问模板**：

> 这次投稿有没有目标期刊/会议的排版模板或征文通知（Word 版最好）？
> - 有 → 按模板来：读模板 docx 的版式（字号、字体、栏数、结构顺序、脚注要求），本 skill 的机制（真尾注+上标[N]+一文一引）不变，版式参数按模板调整
> - 没有 → 用内置双栏期刊模板（题目/作者/单位/摘要/关键词/双栏正文/参考文献/英文部分/作者简介的完整学报版式），直接往下走

注意：内置模板就叫"内置双栏期刊模板"，不要提它出自哪个期刊/会议。

**再收集元信息**（写 meta.json 用）：

| 字段 | 内容 | 备注 |
|---|---|---|
| author | 作者姓名 | 必填 |
| affiliation | 单位+城市+邮编 | 如"（XX大学XX学院，北京 100000）" |
| author_bio | 作者简介 | 如"张三（2000—），男，XX人，XX大学XX学院本科生/硕士生，主要从事XX研究。" |
| contact | 联系方式 | 征文常要求：电话+邮箱，放文末 |
| clc / doc_code | 中图分类号/文献标识码 | 默认 G641 / A，可按选题调 |
| fund / received | 基金项目/收稿日期 | 可选，进第一页脚注 |
| english | 英文题目/作者/单位/摘要/关键词 | **问用户要不要英文部分**——看征稿要求；没有要求就不加 |

用户个人信息（姓名、电话、邮箱等）只写进当次任务的 meta.json，**绝不进入 skill 仓库的任何文件**。

### 第一步：通读草稿，核对引用

1. 草稿应为结构化 markdown（quickwrite/cowrite 的产出即可）：`# 标题`、`**摘要：**`、`**关键词：**`、`## 一、…`/`### （一）…` 标题、正文段落里 `[N]` 标注、文末 `**参考文献：**` + `[N] 条目`
2. 核对每处 `[N]` 标注对应的文献信息是否完整真实（对照用户的参考文献文件夹/素材库）。缺信息的标"[待核实]"列给用户
3. 检查有无同一文献多次引用：有的话跟用户说明一文一引规则——默认保留首次出现、删掉后面的标注；如用户坚持重复引用，走备用方案（references 第 3 节）
4. 参考文献表排序规则：按文中首次出现顺序（脚本会自动重排，重排结果在报告里）

### 第二步：准备输入文件

1. 正文 markdown 就位（必要时先修正标注/补齐参考文献条目）
2. 写 meta.json（字段见第〇步表格；样例结构见 scripts/build_journal_docx.py 顶部 docstring）
3. meta.json 和正文 md 放在用户的论文工作目录，不进 skill 仓库

### 第三步：运行脚本

```bash
python scripts/build_journal_docx.py --md 论文正文.md --meta meta.json --out 投稿版.docx
```

脚本内部：解析 md → 搭三节版式（单栏标题区/双栏正文/单栏英文区）→ 文中 [N] 替换为上标真尾注（一文一引去重+自动重编号）→ 建尾注条目（"参考文献"标题做成不被引用的尾注，紧贴列表）→ 作者简介脚注 → 保存后自动重开文件逐项自检。

### 第四步：转述报告 + 交付

1. 把脚本输出的报告转述给用户：一文一引删了哪几处、编号重排了哪些、未引用的条目删了哪条、自检结果
2. 请用户打开检查三件事：① 文中 [N] 都在右上角；② "参考文献"标题紧贴列表；③ 尾注点击可跳转
3. 交付提醒（重要，都是踩过的坑）：
   - **不要在 WPS 里手动改尾注、加方括号**——会搞出空条目和乱码；有问题重新跑脚本
   - 如果文件被 WPS 重新保存过，检查参考文献是否还在英文部分之前；位置跑了就重跑脚本
   - 用户提供的模板有特殊要求（如指定字体、单栏等）而脚本默认版式不符时，改脚本的 TPL 配置再重跑，不要手动改 docx

## 版式规格速查

内置双栏期刊模板的完整字号/字体/结构规格见 `references/journal-endnotes.md` 第 5 节。新增模板（如某期刊的单栏版式）在 `scripts/build_journal_docx.py` 的 `TPL` 配置里扩展，机制部分（尾注/上标/一文一引/自检）不用动。
