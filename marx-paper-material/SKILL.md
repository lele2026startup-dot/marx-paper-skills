- 先读取同一 skills 根目录下 `marx-paper/references/workflow-contract.md`，沿用本次任务已确认的结构、字数、引用和输出要求；仅询问真正缺失的信息。
- 使用当前可用的搜索、浏览器和文档工具；不强制指定第三方搜索服务。脚本路径相对于所在 skill，执行时解析为绝对路径。
- 引文保留实际读取的来源链和核验状态；未读原件不声称已核原文、版本或页码。学校/期刊模板及任务要求优先。
- 可用时结合 documents/pdf 技能渲染检查；Windows 使用 PowerShell，Python 优先检查当前工作环境提供的运行时和依赖。

# 马理论科材料检索入库

## 这个 skill 做什么

把用户要的文献**找到、抓全、整理好、放进资料库**，一条龙：

1. **检索**：按材料类型路由到合适的来源（经典著作去马克思主义文库，政策文件去官网……）
2. **抓取**：下载全文，处理编码和 HTML 清洗，产出干净的 UTF-8 文本
3. **双格式入库**：每篇材料一个文件夹，文件夹名带日期，内含 TXT + 规范排版 Word
4. **同步导航**：更新资料库的 SOT / AGENTS.md（如果库里有）

**默认完成入库**；用户明确只要查找或下载时按本次范围执行，不额外强制建库。

## 检索工具

使用当前可用的网页检索与页面读取工具；已知 URL 直接读取，动态页面使用可用浏览器，不要求安装指定搜索服务。

## 工作流

### 第〇步：识别材料类型

用户给出的材料一般是这几类，先判断属于哪类（决定去哪找、归哪个目录）：

| 类型 | 例子 | 来源方向（灵活，见 references/sources.md） |
|---|---|---|
| 经典作家原著 | 马恩列毛等的文章、书信 | 中文马克思主义文库（marxists.org）、维基文库 |
| 党内历史文件 | 决议、决议案、会议文件 | 中文马克思主义文库的中央文件选集 |
| 政策文件 | 中央/国务院/部委文件 | 官方网站（gov.cn、新华社、人民日报、教育部等），认准文号 |
| 领导人讲话 | 各时期领导人讲话全文 | 官方网站优先；历史讲话也可走文库 |
| 学术文章/专著节选 | 学者论文、书籍章节 | 知网/爱思想等；常常需要用户提供文件 |

来源路由只是经验优先级，**别写死**——搜不到就换来源，用户给了 URL 就直接抓。

### 第一步：确认存放位置（先提议、再确认）

1. 看用户的资料库：通常在 E 盘下的资料库文件夹，当前工作目录、用户历史路径、用户说明都是线索
2. **读库自己的 `AGENTS.md`**——库的入库约定（目录结构、命名规则、双格式要求）以库自己的 AGENTS.md 为准，那是真源；本 skill 的默认约定只在库没有 AGENTS.md 时兜底
3. 提出建议：归入哪个一级目录、文件夹叫什么名（日期精度、发文机关、文号、重要/不重要后缀，仿照库里已有文件夹的样式）
4. **跟用户确认后再动手**。多篇材料一起列个清单让用户一次确认

默认约定（库里没写时的兜底）：
- 文件夹名：`日期 标题 重要/不重要`，日期精度灵活（`YYYY` / `YYYY-MM` / `YYYY-MM-DD`）
- 政策文件带发文机关和文号：`2020-06 教育部《XXX纲要》（教高〔2020〕3号） 重要`
- 非本目录"主属"作者的材料，文件夹名加「（作者）」，如 `1926-09 军队中政治工作的方法（恽代英） 重要`
- 文件夹内放**同名** `.docx` + `.txt` 各一份

### 第二步：检索与抓取

1. 用当前可用的网页搜索工具 定位全文 URL（查询词带上"全文"和作者/日期；经典著作可加 `site:marxists.org`）
2. 用 `scripts/fetch_text.py` 下载清洗：

```bash
python scripts/fetch_text.py --name "标题" --url "https://..." --out "目标文件夹/标题.txt"
```

脚本自动处理：编码探测（老站点多为 GB18030，见 references/sources.md 的编码规则）、正文提取（去导航/脚注/HTML 标签）、乱码校验并打印报告。多篇材料一次传一个 jobs JSON 批量跑。

3. **抓不到/页面是动态渲染** → 用 agent-browser skill 打开页面抓文本，或请用户提供文件（PDF 可转：mineru-pdf2md）

### 第三步：质量核验（入库前必做）

- **完整性**：开头、结尾抽读，长文核对字数与页面标注是否相符
- **乱码**：脚本报告里 U+FFFD / 锟斤拷数量必须为 0（或仅剩可解释的个别字符）
- **日期**：确认成文/发表日期（文件夹命名要用）——原文标题下的日期行最可靠
- **缺字不猜**：原文有个别缺损字符时，**标出来问用户或查权威版本核对**，严禁凭语感猜字填进去

### 第四步：入库（TXT + Word 双格式）

1. 建文件夹、放入 TXT（文件名 = 标题）
2. 跑排版脚本生成 Word：

```bash
python scripts/format_docx.py "目标文件夹"
```

排版规范（脚本内置）：主标题黑体三号居中加粗、日期行居中、`*` 编者注楷体小字、`##` 小节标题黑体四号加粗、正文宋体小四 1.5 倍行距首行缩进两字符。默认拒绝覆盖已有 docx；获授权后显式传 --overwrite 并留备份。**只写 docx、绝不碰 txt**。

3. 验证：打开 docx 抽查字体/标题/字数与 TXT 一致

### 第五步：同步导航

- 库里有 SOT（如 `00-Source of Truth（文件夹导航）.md`）→ 更新对应目录的内容摘要、顶部更新记录，有"标识性概念速查"类的表也补上
- 库的 AGENTS.md 入库约定若与现实不符（如目录结构变了）→ 跟用户确认后修订
- 把本次入库清单（文件夹名、日期、来源、形态：全文/通稿）汇报给用户

## 安全纪律（写死）

1. **零删除**：资料库里不删任何东西；用户明确要求删也先移到 `E:/垃圾站/`（命名 `YYYY-MM-DD_原文件名`）
2. **覆盖需授权**：已存在的文件要覆盖（如修复乱码文件），沿用本次覆盖授权，显式传 --overwrite；脚本会保留带时间戳备份。未获授权时另存新名
3. **不猜字**：缺损字符宁可标注，不可臆造
4. **临时文件**：过程中产生的临时脚本/中间文件放在库外或 `_` 开头，结束时清理（只清自己建的）
