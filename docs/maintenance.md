# 维护与同步

## 唯一编辑源

源仓库管理 11 个 skill 及其安装元数据；Codex 目录是运行副本，GitHub main 是远程同版本。维护工作区只保存材料、备份、分析和实际机器路径。不能把这四种用途混为多套独立产品。

默认本机源路径为 `~/.pi/agent/skills/marx-paper-skills`，Codex 副本为 `~/.codex/skills/marx-paper*`。源仓库可放其他路径，sync_skills.py 默认取自身所属仓库；安装目录可用 --target 覆盖。别把机器用户名写进共享仓库。

## 每次更新

1. 检查源仓库 git status 与远端 main；保留用户修改，远端有更新时快进同步或先处理冲突。
2. 修改源文件、同步跨模块规则及说明。新增所需资源/关键流程时更新 skills-manifest.json。
3. 运行 `python -m unittest discover -s tests -v`。有脚本改动时再执行相关真实样例；排版效果按目标文字处理器检查。
4. 审阅最终 diff，只提交本次改动；按照用户授权决定是否推送，不强推、不重写历史。
5. 运行 `python scripts/sync_skills.py --apply --backup-dir "备份路径"`。第一次同步或确有授权覆盖被手改安装文件时加 --overwrite-installed；保留备份路径。
6. 推送已授权的 GitHub 更新，再运行 `python scripts/sync_skills.py --check --verify-remote`。必须以成功退出且 consistent=true 为完成依据；未能连接远端或有未提交内容时不能声称三处一致。

## 同步工具的边界

- 哈希包含 SKILL.md、scripts、references、agents 等全部受管理模块文件；不对正文做缩短、转写或自动截断。
- 关键章节和文件缺失时停止，避免把残缺选题流程传播给其他安装。
- Codex 副本有同期手工改动时默认停止，先回到源仓库合并，再备份同步。
- 副本有源仓库未知文件时停止；先确认用途并归档，不自动删除。
- --check 只读，不做自动修复或网络推送。--verify-remote 只核对已提交源与 GitHub main；源有未提交内容即失败。
- 备份包含旧文件与哈希清单。回滚先选定要回到的 Git 版本或备份，恢复源后重新测试和同步；不使用 reset --hard 丢弃用户改动。
- `.marx-paper-sync.json` 是安装目录的本地哈希记录，不是第二个维护源。

## 输出与依赖

抓取与排版脚本默认保护已有输出，--overwrite 仅在本次授权允许时使用，并先备份。临时文件验证成功后发布，失败清理自身临时文件，不替换现有成果。

Web 抓取用标准库 urllib，编码按显式指定、BOM、可信HTTP/HTML声明、严格UTF-8与旧中文编码处理。乱码签名计数为零仍不能代替原文首尾及完整性核对。抓取默认提取正文，保留原URL；注释区裁剪属于正文入库约定，做学术核验时仍须读取完整原件及版本信息。

期刊引注采用一个来源一个真尾注，重复位置使用 NOTEREF 交叉引用域。不要重新采用删除正文标注、共享多个 endnoteReference id 或隐藏空条目的旧方案。若目标 WPS 对域处理有异常，保留全部引用与源稿，报告环境问题，再按目标模板调整，不静默删标。

课程/学位 pipeline 的默认样式不等于能自动适配所有学校模板；字体、行距等不同要求需按真实模板调整并复核。原文核验不由格式脚本完成。
