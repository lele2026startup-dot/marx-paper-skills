# 开发与贡献指南

本文面向修改 skill、脚本、预置和发布版本的维护者或贡献者。安装、调用和获取更新请见 [使用说明](../README.md)。

## 准备开发环境

在自己选择的目录克隆或 fork 本仓库，并保留整个项目结构。仓库管理11个 skill、配套资源、安装清单和测试；工作目录无需采用项目维护者个人电脑上的布局。

脚本使用 Python 3.12 及以上版本。运行现有测试需 `python-docx`、`lxml` 和 pandoc；验证 Word 真实分页另需 Windows、Microsoft Word 和 `pywin32`。按改动涉及的能力准备环境，未完成的验证应明确记录。

## 修改与验证

1. 修改前检查 Git 状态，保留已有和并发改动；确认本次修改范围。
2. 在当前工作检出中维护项目文件。变更资源或关键流程时更新 `skills-manifest.json`，并检查对应的入口、交接规则、说明和安装元数据。
3. 运行相关测试。完整行为测试入口为：

   ```powershell
   python -m unittest discover -s tests -v
   ```

4. 排版脚本的改动还需使用虚构样稿，在目标文字处理器中核对目录、分页、引注位置与跳转；XML检查和视觉验收分开记录。用户真实论文不进入测试目录或提交。
5. 审阅最终差异，只提交本次改动。外部贡献者通过自己的分支或 fork 提交拉取请求；由项目维护者审阅和决定发布。

## 安装工具与开发验证

`scripts/sync_skills.py` 将模块文件复制到指定 skills 目录，并进行哈希核对。它也可供用户从下载包安装，不要求来源目录是 Git 仓库。开发时可指定专用测试安装目录，避免影响正在使用的 skill：

```powershell
python scripts/sync_skills.py --apply --target "测试skills目录" --backup-dir "测试备份目录"
python scripts/sync_skills.py --check --target "测试skills目录"
```

`--target` 省略时默认使用 `~/.codex/skills`；其他智能体的目标目录由使用者按平台要求选择。脚本复制资源，不保证所有智能体均已通过兼容验证。

工具的保护范围：

- 检查所需文件、关键章节和全部受管理模块文件，不截断或改写正文。
- 覆盖已有文件前备份；发现本地编辑时停止，核对并合并后再决定是否使用 `--overwrite-installed`。
- 安装目录有未知文件时停止，不自动删除；先调查用途，再由相应负责人归档。
- `.marx-paper-sync.json` 是安装校验记录。`--check` 只读，结果中的 `consistent` 表示下载／工作检出内容与指定安装目录是否一致。

## 由维护者执行的发布核对

在测试和差异审阅完成后提交变更，按项目授权和协作流程合并、推送或发布版本。不强推、不重写历史来跳过冲突。发布前有上游更新时，先保留本地工作并处理差异。

需要核对当前 Git 检出与其 `origin/main` 是否为同一提交时，可运行：

```powershell
python scripts/sync_skills.py --check --target "待核对的skills目录" --verify-remote
```

这项发布校验要求干净的 Git 工作区、可访问的远端和正确配置的 `origin/main`，同时核对当前检出、指定安装目录与远端提交。它不负责推送，下载 ZIP 的用户不需要执行。无法连通远端或存在未提交内容时，不声称发布核对通过。

维护者个人机器的检出路径、安装位置、备份位置和多个工作副本之间的安排，写在各自的本地维护记录中，不作为项目通用安装要求。

## 维护内容时的约定

- 引文规则与环节交接由 `marx-paper/references/workflow-contract.md` 统一维护，用户的具体任务要求优先。
- 预置登记于 `marx-paper/references/format-presets.json`。新增编号保留既有ID和中文名，配套匿名参数、说明、行为验证及安装清单；正式／盲审变体不必新建 skill。
- 个人身份、私人模板、原始规范文件、机器绝对路径和生成样稿不进入公共提交；测试样例须虚构。
- 期刊重复引用保留全部位置，一个来源一个真尾注，其余位置用交叉引用域。不能以条目去重为由删除正文引用。
- 抓取与排版默认保护已有成果，输出覆盖须获相应授权并保留备份。原文核验和实际版面验收仍在具体论文任务中完成。
